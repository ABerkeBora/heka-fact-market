1. `npm ci`, `cp .env.example .env`, `forge build`. Run Ollama with `qwen3:4b`. Install the sponsor's standard BSV Desktop wallet, select **Testnet** and obtain free test sats. The app hard-rejects mainnet. WalletClient uses localhost; private keys never enter this application.
2. Run `npm run dev`, open `/bsv`, connect the standard wallet, then explicitly fund the isolated test counterparty once with the shown capped5000test sats. This is a local independent test role, not a real second customer. Stop the server before mutating CLIs; they acquire the same process lock.
3. `npm run bsv:bootstrap` prepares a1900sat CP-owned BRC-100 derived UTXO with a500sat fee cap. It writes only ignored `.local/bsv/native/counterparty-source.json` and a canonical signed journal. Publish the exact saved transaction with `npm run bsv:publish-saved -- .local/bsv/native/cp-bootstrap.json`. Reconcile that existing hash; never replace an uncertain request.
4. An optional standard-wallet fee sponsor can run `npm run bsv:sponsor -- seed --accept-testnet-seed-12000-fee-cap-500`. This prepares a self-owned12000sat UTXO and `.local/bsv/fee-sponsor-public.json`; publish the exact saved journal with `npm run bsv:publish-saved -- .local/bsv/native/sponsor-seed.json`. A separate sponsor may instead supply the same public source-BEEF schema. The sponsor spends6000deployment fee and receives6000 back; it never receives principal or controls the contract. These helpers are typechecked; their optional fresh-profile transactions were not executed during this pilot.
5. Restart the app. At `/bsv/native`, request a supported ETH/USD goal. One runtime LLM call chooses an allowlisted offset and side. A deterministic validator pins the source, window, threshold, amounts and recipients. Review and prepare the1000sat buyer mandate in the standard wallet; the counterparty signs its owned input. The plan remains ignored under `.local/bsv/native/funding-plan.json`.
6. Stop the app; the configured fee owner runs `npm run bsv:sponsor -- sign .local/bsv/native/funding-plan.json`. The local CLI only signs if it owns the configured source, the observation window is still future, all three participant/source amounts match, both participant signatures are valid, and the immutable2000/900/6000outputs and exact6000fee match. It writes one ignored `funding-signed.json`. Never copy a sponsor key into this repo or use a coordinator's absolute helper path.
7. Restart, then **Start native agent**. Initial deployment and later claim reuse their canonical signed hashes across uncertain broadcasts. Only actual `SEEN_MULTIPLE_NODES`, `ACCEPTED_BY_NETWORK` or `MINED` is accepted; `RECEIVED` remains pending. The agent is capped to six free oracle calls, one deployment, one payout and fixed fees. No top-up occurs. The page shows exact observation/refund timing and the first-valid-spend boundary.
